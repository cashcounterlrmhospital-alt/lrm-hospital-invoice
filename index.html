Online sync needs your own Supabase project. This file cannot create a database account or securely host patient/customer records by itself. For real business use, enable Row Level Security and authentication; do not use a service-role key here.
Database SQL setup instructions

Create a Supabase project, open SQL Editor, then run the SQL below. This simple starter table uses RLS. The example policy allows anon access for quick testing and is NOT suitable for real customer data; replace it with authenticated-user policies before production.

create table if not exists public.invoices ( id text primary key, invoice_no text not null, invoice_date date, payload jsonb not null default '{}'::jsonb, updated_at timestamptz not null default now() ); alter table public.invoices enable row level security; -- DEMO ONLY: open anon policies for initial test; not safe for real data. create policy "demo anon select" on public.invoices for select to anon using (true); create policy "demo anon insert" on public.invoices for insert to anon with check (true); create policy "demo anon update" on public.invoices for update to anon using (true) with check (true); create policy "demo anon delete" on public.invoices for delete to anon using (true);

Local browser history is kept as a fallback. Configure the same project URL/key on each device to use the same online invoice table. Use “Download PDF / Print”, then choose “Save as PDF” in the print window. The PDF includes customer name, invoice date and item descriptions.
